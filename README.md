## 프로젝트 개요

무역 실무에서 활용 가능한 글로벌 거래처 DB를 설계하고, 담당자 교신 이력을 분석하여 오랫동안 연락이 끊긴 업체를 탐지하는 리스크 관리 시스템을 구축했습니다.

글로벌 통상 환경에서 수출입 실적, 바이어 연락처, 관세율, 선하증권(B/L) 등 무역 실무 데이터를 MySQL 환경에서 체계적으로 관리하고 자산화함으로써, 직관이 아닌 데이터 기반의 의사결정 역량을 내재화하는 것을 목표로 합니다.

## 프로젝트 1 (기초) — 글로벌 거래처 명부 DB

**목적:** 바이어·서플라이어 업체 정보를 통합 관리하는 마스터 DB 구축

**핵심 SQL:**
- `CREATE TABLE` — company, contact 테이블 생성
- `INSERT` — 업체 및 담당자 데이터 입력
- `SELECT + WHERE` — 국가·신용등급 필터링 조회
- `UPDATE` — 담당자 이메일 등 정보 갱신

**주요 쿼리 결과:**
- 전체 업체 목록 조회
- 국가별 필터링 (`WHERE country = 'USA'`)
- 업체-담당자 JOIN 통합 조회
- 최신순 정렬 (`ORDER BY last_contact_date DESC`)

## 프로젝트 2 (활용) — 담당자 연락망 및 교신 이력

**목적:** 교신 이력 데이터를 분석하여 오랫동안 연락이 끊긴 고위험 업체 자동 탐지

**핵심 SQL:**
- `JOIN` — 업체-담당자 테이블 연결
- `WHERE + 날짜 비교` — 교신 공백 고위험군 추출
- `ORDER BY` — 최근 교신일 기준 정렬

**활용 컬럼:**

| 컬럼 | SQL 역할 | 무역 실무 활용 |
|------|----------|----------------|
| company_id (FK) | JOIN 키 | 업체-담당자 테이블 연결 |
| contact_name | SELECT 출력 | 교신 대상 실무자 확인 |
| last_contact_date | WHERE / ORDER BY | 교신 공백 기간 산정 및 우선순위 정렬 |

**비즈니스 인사이트:**
- Hanoi Trading (베트남) — 마지막 교신 2025년 11월, 최우선 재접촉 대상
- Tokyo Logistics (일본) — 교신 공백 3개월 이상, 계약 갱신 검토 필요
- 교신 데이터 수치화로 '느낌'이 아닌 '데이터' 기반 파트너십 리스크 관리 실현
